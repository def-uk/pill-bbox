# YOLO26m 제외 결정 재검토

10.31에 YOLO26m을 베이스라인 점수 하나로 후보에서 뺐다가, 11.02에 근거가 부족하다는 피드백을 받고 다시 넣었다. 이 문서는 그때 남기지 못한 고찰을 지금 있는 실험 기록(PR #98–#120)으로 정리한 것이다.

## 요약

- **베이스라인 0.18은 YOLO26m 구조의 한계가 아니었다.** 외부 데이터를 같은 방식(외부 전용 알약은 배경, A안)으로 넣자 YOLO26m 0.45379, YOLO11m 0.44885로 YOLO26m이 오히려 조금 높았다.
- 0.18의 원인으로 확인된 것은 **적은 학습량**이다. 평가 헤드를 바꾼 실험(NMS → NMS-free)은 0.179 → 0.184로 원인이 아니었다.
- 최종 점수 차이(YOLO11m 0.63060, YOLO26m 0.60721)는 분할, 증강, GPU가 서로 다르고 seed 하나로 한 번씩만 돌린 결과다. **두 모델 중 어느 쪽이 더 정확한지 이 기록으로는 정할 수 없다.**

## 2. 같은 단계끼리 비교

두 모델이 거친 단계를 나란히 놓으면 다음과 같다. 점수는 모두 캐글 mAP@[0.75:0.95]다.

| 단계 | YOLO11m | YOLO26m | 비고 |
|---|---|---|---|
| ① 대회 사진만, 30 에폭 | 0.29946 | 0.17877 (NMS 헤드)<br>0.18437 (NMS-free 헤드, #111) | 분할이 다름(아래 3절) |
| ② 대회 사진만, 100 에폭 | 0.41485 (#105) | **돌리지 않음** | YOLO26m만 이 단계를 건너뜀 |
| ③ + AI Hub, 외부 전용 알약 = 배경 (A안) | 0.44885 (#105) | **0.45379** (#112) | YOLO26m은 24 에폭이 best |
| ③-1 위 + 모자이크 끔 | 0.46281 (#107) | 0.44731 (#113) | 방향이 서로 반대. 차이는 노이즈 범위 |
| ④ + 외부 전용 알약을 새 클래스로 학습·제출 (B안) | **0.63060** (#109) | 0.60721 (#114, copy-paste 포함)<br>0.60008 (#116, 검수 데이터) | 조건이 다름(아래 3절) |
| ⑤ 위 + 각인 OCR 재분류 | 내려감 (보고서 4.5) | 0.58768 (#120) | 두 모델 모두 효과 없음 |

읽는 법:

- ①에서 0.12 벌어졌던 차이가 ③에서 사라졌다(+0.005로 역전).
- ①→③ 상승폭은 YOLO11m이 1.5배(0.299 → 0.449), YOLO26m이 2.5배(0.184 → 0.454)였다. 다만 YOLO11m은 ②의 에폭 증가를 따로 거쳤기 때문에 두 값은 같은 변화량이 아니다.

## 3. 0.18의 원인: 가설별 판정

| 가설 | 근거 | 판정 |
|---|---|---|
| H1. 평가 헤드가 맞지 않았다 | YOLO26은 NMS 없이 쓰는 one2one 헤드가 기본인데, 베이스라인은 `nms=True`로 보조 헤드(one2many)를 평가했다(#111). 보조 헤드의 손실 가중치는 학습이 진행될수록 0.8 → 0.1로 줄어든다. 하지만 기본 헤드로 바꿔도 0.17877 → 0.18437이었다 | **기각.** 10.31에 "평가 헤드를 바꿔도 0.18"이라고 한 실험이 이것이다 |
| H2. 학습 데이터가 너무 적었다 | 대회 train은 193장(holdout 기준)이다. AI Hub 5,842장을 더해 train이 31.3배가 되자 0.45379가 됐고, 같은 조건의 YOLO11m(0.44885)과 같은 수준이 됐다 | **지지.** 베이스라인 차이를 설명하는 가장 강한 근거 |
| H3. 에폭이 부족하거나 조기 종료가 빨랐다 | 베이스라인은 30 에폭·patience 5였다. YOLO11m은 100 에폭으로 늘리자 +0.115 올랐다. YOLO26m은 ②(대회 사진만 100 에폭)를 돌리지 않았고, 노트북 출력을 지워서 베이스라인이 몇 에폭에서 멈췄는지도 남아 있지 않다 | **미확인.** H2와 분리하려면 ② 실험이 필요하다 |
| H4. 비교 조건이 처음부터 달랐다 | YOLO26m은 노트북이 만든 `combo_v1_s42` 단일 holdout(train 193, val 39)을 썼고, YOLO11m 베이스라인은 `combofix` 5 fold 분할로 학습했다(#102). 0.29946이 어느 fold 제출인지는 기록에 없다 `[확인 필요]`. GPU도 T4·A100·L4·MPS로 섞여 있고 모두 seed 42 한 번이다 | **확인.** ①의 점수 차이에는 모델 말고도 분할과 실행 환경 차이가 섞여 있다 |
| H5. 검증과 캐글이 어긋났다 | YOLO26m 베이스라인은 val 0.593인데 캐글 0.184였다. test 사진의 40%에 대회 밖 알약이 있고(#114), 검증에는 조합 단위 분할 뒤에도 세팅 누수가 남아 있다(보고서 5.2) | **두 모델에 공통.** YOLO26m만 낮은 이유는 아니다 |

### H2를 어떻게 해석할까

YOLO26의 기본 헤드는 정답 박스 하나에 예측 하나만 짝짓는 one-to-one 할당으로 학습한다. 그래서 NMS가 필요 없지만, 한 정답에서 얻는 학습 신호가 one-to-many 할당(YOLO11)보다 적다. YOLOv10(Wang 등, 2024)이 one-to-many 보조 헤드를 같이 학습하는 이중 할당을 쓴 이유도 이것이다. 정답 박스가 사진당 3–4개, 학습 사진이 193장인 우리 데이터에서는 이 차이가 크게 드러났을 수 있다. 다만 **이 해석은 문헌에 기댄 가설이고, 우리 실험으로 직접 확인한 것은 아니다.**

## 4. 결론

- 10.31의 제외는 근거가 부족했다. 베이스라인 점수만으로는 구조 차이, 학습량 차이, 분할 차이를 구분할 수 없었다. 논문을 근거로 고른 후보라면 같은 데이터 전략을 적용한 뒤에 판단했어야 했다.
- 최종 단계의 차이 0.023(0.631 vs 0.607)도 같은 조건의 비교가 아니다. YOLO26m 쪽에는 copy-paste가 더 들어갔고, 분할과 GPU가 다르며, seed가 하나다.
- 그래서 최종 모델 선택의 근거는 **"정확도가 더 높아서"가 아니라** 다음 두 가지로 적어야 정직하다.
  1. 우리가 낸 제출 중 최고점이 YOLO11m이었다(0.63060).
  2. 웹 앱(ONNX)에 이미 YOLO11m으로 연동·검증을 마쳤다. Android·iOS는 아직 검증하지 않았다.
- 보고서 3장은 "앱 변환의 쉬움"을 YOLO11m 선택 이유로 들었다. 그런데 같은 보고서 3.3은 YOLO26이 DFL 제거와 NMS 없는 출력으로 변환이 더 쉽고 CPU에서 빠르다고 적었다. 이 부분은 위 2번("이미 연동을 마쳤다")으로 고쳐야 앞뒤가 맞는다.

## 5. 앞으로의 후보 탈락 규칙

1. 후보는 **같은 분할, 같은 에폭·조기 종료, 같은 데이터 전략**을 적용한 뒤에만 비교한다.
2. 낮은 점수가 나오면 빼기 전에 원인 가설을 세우고, 가설 하나당 실험 하나로 확인한다(이 문서 3절의 표 형식).
3. 차이가 seed 간 편차보다 작으면 "차이 없음"으로 본다. 그러려면 최소 seed 3개를 돌린다.
4. 결정은 이 문서처럼 날짜, 근거, 영향받는 사람과 함께 기록한다.
